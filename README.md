# MiniLagerverwaltung

Desktopanwendung zur Lagerverwaltung, entwickelt mit **Lazarus** (Free Pascal) und einer **Firebird**-Datenbank. Objektorientiert aufgebaut, mit klarer Trennung von Oberfläche, Fachlogik und Datenhaltung.

## Funktionen

- Artikel hinzufügen, bearbeiten und löschen
- Wareneingang und Warenausgang buchen, mit Datum und Uhrzeit
- Der Bestand ändert sich nur durch Buchungen
- Ein Warenausgang darf den Bestand nicht negativ machen
- Gebuchte Bewegungen werden nie gelöscht oder geändert, sondern per **Storno** (Gegenbuchung) ausgeglichen
- Artikel mit Bewegungen können nicht gelöscht werden
- Eingabeprüfung mit verständlichen Meldungen

## Projektstruktur

| Datei | Klasse | Aufgabe |
|---|---|---|
| `uArtikel.pas` | `TArtikel` | Datenklasse eines Artikels |
| `uLagerService.pas` | `TLagerService` | Fachregeln und Datenbankzugriff |
| `Unit1.pas` | `TFormMain` | Benutzeroberfläche |

## Voraussetzungen

- Lazarus mit Free Pascal
- Firebird-Server (ab Version 3.0)
- `fbclient`-Bibliothek (`fbclient.dll` unter Windows, `libfbclient.so` unter Linux), passend zur Bitversion des Programms
- Optional: DBeaver zum Ansehen der Daten

## Datenbank einrichten

Führe in DBeaver (Auto-Commit an) dieses Skript aus:

```sql
CREATE TABLE ARTIKEL (
  ARTIKELNUMMER  VARCHAR(30)    NOT NULL PRIMARY KEY,
  BEZEICHNUNG    VARCHAR(100)   NOT NULL,
  EINZELPREIS    DECIMAL(10, 2) NOT NULL,
  MINDESTBESTAND INTEGER        NOT NULL,
  BESTAND        INTEGER DEFAULT 0 NOT NULL,
  CONSTRAINT CHK_BESTAND CHECK (BESTAND >= 0)
);

CREATE TABLE BEWEGUNG (
  ID            INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  ARTIKELNUMMER VARCHAR(30) NOT NULL,
  BEWEGUNGSART  VARCHAR(10) NOT NULL,
  MENGE         INTEGER NOT NULL,
  ZEITPUNKT     TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
  STORNO_VON    INTEGER,
  BEMERKUNG     VARCHAR(200),
  CONSTRAINT FK_BEW_ARTIKEL FOREIGN KEY (ARTIKELNUMMER)
    REFERENCES ARTIKEL (ARTIKELNUMMER),
  CONSTRAINT CHK_BEW_ART CHECK (BEWEGUNGSART IN ('ZUGANG', 'ABGANG')),
  CONSTRAINT CHK_BEW_MENGE CHECK (MENGE > 0)
);

ALTER TABLE BEWEGUNG ADD CONSTRAINT FK_BEW_STORNO
  FOREIGN KEY (STORNO_VON) REFERENCES BEWEGUNG (ID);

ALTER TABLE BEWEGUNG ADD CONSTRAINT UQ_BEW_STORNO UNIQUE (STORNO_VON);

CREATE EXCEPTION E_BEWEGUNG_GESCHUETZT
  'Bewegungen duerfen nicht geaendert oder geloescht werden. Bitte stornieren.';

SET TERM ^ ;

CREATE TRIGGER BEWEGUNG_SCHUTZ_BD FOR BEWEGUNG BEFORE DELETE AS
BEGIN
  EXCEPTION E_BEWEGUNG_GESCHUETZT;
END^

CREATE TRIGGER BEWEGUNG_SCHUTZ_BU FOR BEWEGUNG BEFORE UPDATE AS
BEGIN
  EXCEPTION E_BEWEGUNG_GESCHUETZT;
END^

SET TERM ; ^
```

## Verbindung konfigurieren

Trage die Zugangsdaten im Objektinspektor von Lazarus bei `IBConnection1` ein:

- `HostName`
- `DatabaseName` (Pfad oder Alias)
- `UserName`
- `Password`
- `CharSet` = `UTF8`
- `Connected` = `False`

> **Hinweis:** Lade niemals echte Zugangsdaten auf GitHub hoch. Entferne das Passwort aus `Unit1.lfm`, bevor du committest.

## Starten

1. `MiniLagerverwaltung.lpi` in Lazarus öffnen
2. **Start → Alles neu bauen**
3. Programm mit **F9** starten

## Bedienung

- **Hinzufügen:** Felder ausfüllen und auf *Hinzufügen* klicken
- **Bearbeiten:** Artikelnummer eingeben, Werte ändern, auf *Speichern* klicken
- **Löschen:** Artikelnummer eingeben und bestätigen
- **Wareneingang / Warenausgang:** Artikelnummer und Menge eingeben
- **Bewegung stornieren:** ID aus der Bewegungstabelle eingeben
